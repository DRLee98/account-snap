# OCR-002 계좌번호/은행명 파싱 로직

## 문서 정보
- ID: OCR-002
- 생성일: 2026-05-28
- 참조문서: [OCR-001 CLOVA OCR API 연동](OCR-001-clova-integration.md), [DAT-001 Account 데이터 모델](DAT-001-account-model.md)
- 관계: 의존

## 목적

CLOVA OCR이 반환한 텍스트 배열에서 (1) 계좌번호 (2) 은행명 (3) 가능하면 예금주명을 식별·정규화.

## 입력

[[OCR-001]]의 `OcrResult` — 각 텍스트 박스의 `inferText`, `boundingPoly`(좌표), `inferConfidence`.

## 출력

```ts
type ParsedAccount = {
  accountNumber: string;   // 정규화 (하이픈/공백 제거, 숫자만)
  bankName: string;        // 표준 은행명 (예: "국민은행")
  bankCode?: string;       // 은행 코드 (있으면)
  holderName?: string;
  confidence: number;      // 0~1 종합 신뢰도
  candidates?: ParsedAccount[]; // 여러 후보가 나온 경우 (사용자 선택)
};
```

## 파싱 단계

### 1. 계좌번호 후보 추출

- 정규식: `/\d[\d\-\s]{9,}\d/` (숫자 10자리 이상, 하이픈/공백 허용)
- 후보별로 하이픈/공백 제거 후 길이 검증 (10~16자리)
- 한 매치의 숫자가 16자리를 넘으면 번호 두 개가 붙은 것 → 공백으로 분리.
  단, 분리된 조각이 **모두** 그 자체로 10~16자리일 때만 분리한다
  (한 번호가 여러 필드로 쪼개진 `"010" "1234" "5678"` 케이스를 잘못 합치지 않기 위함)
- 전화번호 형태(10~11자리 + 010/011/016/017/018/019 시작)는 **버리지 않고 문맥으로 판별** — 아래 1-1 참조

### 1-1. 평생계좌 vs 전화번호 판별

계좌번호가 곧 휴대폰 번호인 평생계좌(신한·국민·하나·농협 등)가 있어서, 접두사만으로 제외하면
평생계좌를 통째로 놓친다. 숫자 앞뒤 24자 문맥에서 가장 가까운 힌트 단어로 판단한다.

- 계좌 힌트: `평생계좌`, `평생`, `계좌`, `입금`, `송금`, `이체`, `통장`, `예금주` + 모든 은행 별칭
- 전화 힌트: `전화`, `연락처`, `휴대폰`, `문의`, `상담`, `팩스`, `Tel`, `H.P`, `phone` 등
- 앞쪽(before) 힌트가 뒤쪽(after) 힌트보다 강하다 — 뒤 단어는 다음 항목의 라벨인 경우가 많음
  (`"연락처 010-… 입금 국민은행 …"` → 앞의 `연락처`가 이김). 뒤쪽 거리에 +24 페널티.
- 판정 결과
  - **전화** → 후보에서 제외
  - **평생계좌** → 일반 계좌와 동일하게 취급
  - **문맥 없음** → 제외하지 않고 신뢰도 ×0.5 후순위 후보로 유지 (사용자가 선택)
    - 단, 이미지 어딘가에 `평생계좌`가 있으면 평생계좌로 승격
- 후보 정렬: 일반 계좌 > 평생계좌 > 문맥 없음 (동순위는 등장 순서)
- 12자리 이상은 `010`으로 시작해도 전화번호 검사를 하지 않는다 (일반 계좌번호)
- 표시 포맷은 은행 그룹 패턴보다 전화번호 형태가 우선 (`010-1234-5678` / `011-123-4567`)

### 2. 은행명 식별

- 사전 정의 은행명 리스트 매칭 (정확/부분 일치)
- 한글 표준명 + 영문 약어 + 흔한 오타 패턴 (예: "국민" / "KB" / "kookmin")
- 매칭된 은행 → 표준명 + bankCode 매핑

```ts
const BANKS = [
  { code: '004', names: ['국민은행', 'KB', '국민'] },
  { code: '088', names: ['신한은행', '신한'] },
  { code: '020', names: ['우리은행', '우리'] },
  { code: '081', names: ['하나은행', '하나'] },
  // ... 카카오뱅크, 토스뱅크, IBK, NH, SC, 우체국 등
];
```

### 3. 예금주명 추출 (옵션)

- "예금주" 단어 근처 텍스트 박스 (boundingPoly 좌표 기준)
- 한글 2~4자 + 영문 1~30자

### 4. 신뢰도 계산

- 계좌번호 매칭 confidence (CLOVA inferConfidence 평균)
- 은행명 매칭 확실성 (정확 1.0, 부분 0.7, 추정 0.4)
- 종합 가중 평균

## 엣지 케이스

- 한 이미지에 계좌 여러 개 → `candidates`로 다 반환, UI에서 선택
- 은행명 못 찾으면 → `bankName: ''` + UI에서 사용자 선택 드롭다운
- 계좌번호만 있고 은행명 없음 → 일부 은행은 계좌 prefix로 추정 가능 (정확도 낮음, 보조용)

## 수정 이력

### 2026-08-04 — 평생계좌(전화번호 형식) 인식

기존에는 `010/011/016/017/018/019`로 시작하는 숫자를 전화번호로 간주해 후보에서 무조건
제외했다. 계좌번호가 휴대폰 번호인 평생계좌가 통째로 인식되지 않았고, `010`으로 시작하는
12자리 이상 일반 계좌번호까지 같이 버려졌다.

- 접두사 무조건 제외 → 앞뒤 문맥 힌트 기반 판별로 교체 (위 1-1)
- 전화번호 형태 판정을 10~11자리로 한정 (12자리 이상 오탐 제거)
- 번호 두 개가 붙어 한 매치로 잡히던 문제 분리 처리 — 이전에는 길이 초과로 둘 다 사라졌음
- 중복 번호 후보 dedup
- `formatAccountByBank`에 전화번호 형태 그룹화 추가
